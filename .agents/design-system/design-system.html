The six laws

design.md §1–§5

Everything else in this document is a consequence of these. When a new screen looks wrong, it has almost always broken one of them.

Contrast through opacity, not colour weight. Depth is built by stacking translucency — white/5 → white/10 → white/20 — never by reaching for a darker or more saturated fill.

law 01Breaking it produces the muddy, heavy look the glass base exists to avoid.

One glowing element per view. The active state or the primary action — not both. Two glows and neither reads as focal.

law 02On this page the budget is spent on the word "lime" in the title.

Every number is monospaced. Money, IDs, dates, counts, durations. Values must not shift width between renders, and mono signals "this is precise".

law 03font-numbers · JetBrains Mono · tabular-nums

Nothing is sharper than 12px. The radius floor is rounded-xl. There is no rounded-lg anywhere in the product.

law 04A single square corner reads as a bug, not a variation.

Motion comes from one file. Every transition uses a shared variant from @/lib/motion. No hand-rolled tween, ever.

law 05Ad-hoc easing is how a system stops feeling like one system.

Cards compose on Surface. Never a raw <div> with background utilities. The primitive owns the blur, border, elevation and reveal.

law 06Hand-built cards drift within a sprint.

Surfaces

design.md §4 · globals.css

Five registers. Each one is a live specimen below — the blur and border you see are the values the app ships, not an approximation of them.

.ds-frost The canonical premium card. 28px blur + 150% saturate. Hero and KPI surfaces.
.glass-panel Light surface on the canvas — top nav, filter bars, KPI cards.
.glass-dark Primary content panels and list containers.
.glass-blue — no current caller Specified for detail panes nested inside a dark panel. Surface variant="blue" is instantiated once in the whole repo — on this style guide. Read the note below before using it.
.ds-menu Opaque by design. Menus sit over arbitrary content, where blur smears detail but keeps contrast — a lime chip underneath would read straight through.

The nesting model

Depth runs one direction: dark holds mid, mid holds translucent white. Putting glass-panel inside glass-dark inverts the contrast and breaks the model.

.glass-dark — content panel
.glass-blue — detail pane
white/10 — line item · hover raises to white/20

This model is specified but no longer in use, and that is worth knowing before you build on it. Counting Surface variants across the product: panel 64, frost 5, dark 1, accent 0, blue 0.

measured, not assumed Re-counted 2026-08-21 by attributing every variant= to the component it actually sits on. The earlier figures — frost 9, dark 4, accent 1 — also counted StatTile, AccentButton and GlassPanel variants, which are different components with the same prop name. Excludes this style guide, still the only caller of the blue surface.

The nesting model came from a master–detail layout — a list and a detail pane sharing one dark container — on the Invoices page, which design.md names as the reference template for the product. That page had no Invoice model and no API route behind it: it was mock data throughout, and it was deleted in the 2026-07-24 UI reset. Everything rebuilt since composes flat panel cards directly on the canvas instead of nesting panes inside a dark container.

why it went quiet The colour outlived the layout it was invented for.

So: use panel on the canvas as the default. Reach for dark and blue only if you are genuinely rebuilding a master–detail screen — and if you do, you are the first, so expect to find gaps.

Motion

lib/motion.ts

One signature curve. EASE_LUX leaves fast and settles slowly, which is what makes an interface feel responsive without feeling abrupt. Run them side by side — the lime dot is the system, the steel dot is linear.

EASE_LUX — cubic-bezier(.22, 1, .36, 1)
linear — for comparison only, never shipped

--dur-fast: 160ms

hover, colour, small state

--dur-base: 280ms

entrances, panel reveals — the default

--dur-slow: 520ms

count-ups, meter fills, hero sequences

SPRING — stiffness 420 · damping 32 · mass 0.7

interactive lift and pressSnappy but composed. Never bouncy.

Reduced motion is a contract, not a courtesy. Count-ups always land on their final value, entrances resolve to their end state, and nothing depends on an animation completing for the interface to be usable.

Do & Don't

design.md §2 · v2 rules

Do

  • Compose on Surface. It owns blur, border, elevation and reveal.
  • Spend the glow budget once — active state or CTA, never both.
  • Put every money value, ID, count and duration in font-numbers.
  • Layer white/5 → white/10 → white/20 for depth on dark surfaces.
  • Take all motion from @/lib/motion, and let reduced motion resolve to the end state.
  • Keep the shadow tint blue-violet so elevation belongs to the canvas.

Don't

  • Use brand-accent as a large background. It is a signal, and a signal cannot be a field.
  • Reach for blue or purple SaaS gradients. The palette is neutral plus lime, on purpose.
  • Nest glass-panel inside glass-dark — the contrast inversion breaks depth.
  • Ship rounded-lg or sharper. 12px is the floor.
  • Write a one-off transition object, however small.
  • Add new remixicon usage. React Icons (Fi) only.
