# UI reset — 2026-07-24

> Status: executed. Owner: frontend.
> Supersedes the incremental page-by-page plan in
> [`template-adoption.md`](../guides/template-adoption.md) §5b/5c — that plan (replace-then-delete, one
> page at a time, app stays runnable throughout) was in progress and had shipped a rebuilt
> Dashboard when the user pivoted to a full reset instead.

## What happened

The user asked to delete the entire old UI down to a single surviving route,
**`http://localhost:5173/design-system`**, keeping only the underlying business-logic layer
(hooks/services/api/context/utils) on disk, unwired. Confirmed explicitly across two rounds of
clarifying questions: yes, this includes the just-rebuilt Dashboard (not only the pre-existing
old pages); "logic" means the top-level `hooks/`, `services/`, `api/`, `context/`, `utils/`,
`types/` directories, kept as-is but no longer imported by any page.

This is a deliberate, larger reset than the incremental plan — not a correction of it.

## What was removed

**141 tracked files** (`git rm -rf`) + 4 untracked files/dirs from the still-in-progress
structural-scaffold work (`git rm` can't touch untracked paths, so those were removed directly):

- All 13 old pages (`AIChat`, `AccountSettings`, `Auth`, `BugTrackerApp`, `Calendar`, `Chat`,
  `ChatNew`, `ChatOptimized`, `Dashboard` — including the shadcn/motion rebuild from earlier this
  session, `Homepage`, `Invoices`, `NotePage`, `OptimizationCalendar`) plus `pages/feature/about/*`
  and `pages/structural/*` (the 5 template-ported scaffolds).
- Every feature component folder under `components/ui/` except `note/utils/` (kept — see below):
  `accountsettings/`, `bugtracker/`, `calendar/`, `chat/`, `dashboard/`, `homepage/`, `invoices/`,
  `product/`, `resources/`, plus `note/{NoteDashboard,NoteEditor,NoteShare,ShareNoteModal}.tsx`.
- `components/charts/*` (13 Recharts widgets), `components/card/*`, `components/layouts/*`
  (Sidebar/Topbar/SideNav — the old app chrome) and `components/layouts/structural/*`.
- `components/common/{GridDotsPanel,IconButton,IconLabel,PrincipleCard}.tsx`, all of
  `alert/` except `Toast.tsx` (kept — `ToastContext` renders it), all of `client-error/` and
  `server-error/`.
- `layouts/{Layout,LayoutAbout}.tsx`, `routes/ProtectedRoute.tsx`.
- `components/ui/alert.tsx` (the shadcn Alert built for the Dashboard rebuild — only consumer was
  Dashboard, so it went with it).
- Orphaned CSS: `styles/components/{calendar,loading,socalmedia,structural-luxe}.css` and their
  `index.css` imports.

## What survives, and why

**The route.** `pages/DesignSystem.tsx` and its full dependency tree:
`components/design-system/*` (all 12 primitives + `index.ts`), `components/common/layout/*`
(`PageHeader`, `GlassPanel`, `KpiCard`, `PillTabs` — re-exported through the design-system barrel),
`components/common/ErrorBoundary.tsx`, `lib/motion.ts`, `lib/utils.ts` (the shadcn `cn()` helper).

**The logic layer, unwired.** `hooks/*` (7 files), `services/{api,auth}.ts`, `api/{client,config}.ts`,
`context/{Auth,Theme,Toast}Context.tsx` (still wrap the app in `main.tsx` — global providers, not
page UI), `utils/*` (7 files), `types/*` (10 files). Nothing currently imports most of these; they
compile clean and are ready to be wired into whatever gets rebuilt first.

**One non-obvious keep: `components/ui/note/utils/*`.** This lives inside a `components/ui/`
feature folder, not the top-level `hooks/`/`services/` directories — but `hooks/useNoteAiChat.ts`
and `hooks/useNoteList.ts` import directly from it (`noteAi.ts`, `noteApi.ts`, `noteTypes.ts`).
Deleting it would have broken two of the hooks this reset was explicitly supposed to preserve.
Checked via grep before deleting anything, not after.

**Also deleted, not kept "unwired": `LoadingSpinner.tsx` and `ProtectedRoute.tsx`.** Both were
UI/routing scaffolding rather than data logic, and their only remaining consumer after the page
deletions was each other (`ProtectedRoute` rendered `LoadingSpinner`) plus the old `AppRoutes.tsx`.
With no protected routes and no page-level loading states left, keeping either served no purpose.

## New `routes/AppRoutes.tsx`

Two routes: `/design-system` renders the page; `*` redirects there. No `Layout`, no
`ProtectedRoute`, no `Suspense`/lazy-loading — none of that machinery has a job anymore with one
static page. `ThemeProvider`/`AuthProvider`/`ToastProvider` still wrap the tree in `main.tsx`
(app-level infra, not page UI — left alone).

## Verification

Before any file was touched: grepped every hook's import list against every folder marked for
deletion, to make sure "keep the logic" wasn't going to ship with silently broken imports.
`tsconfig.app.json` has `"include": ["src"]`, so **every file under `src/` type-checks whether or
not anything imports it** — an orphaned hook with a dangling import would fail the build even with
zero consumers. This is why the note/utils exception above was caught in advance rather than as a
build failure.

After: `tsc -p tsconfig.app.json --noEmit` clean. `eslint src` reports 11 pre-existing
issues (`AuthContext`/`ThemeContext`/`ToastContext` fast-refresh warnings, `iconMapping.ts`
`any` types, a `useCalendarEvents.ts` deps warning, one unused var in `note/utils/index.ts`) —
all in kept logic files, all pre-dating this reset, none introduced by it. Scoped eslint run over
just `routes/AppRoutes.tsx` + `pages/DesignSystem.tsx` + `components/design-system` + `lib`: clean.

Browser: `/` and `/dashboard` both redirect to `/design-system` and render correctly (network
panel shows fresh 200s for every design-system module). The console briefly showed a batch of
`[vite] Failed to reload ...` messages for the just-deleted files — that's Vite's HMR reacting to
files disappearing out from under its module graph mid-session, not a runtime error; a fresh
network trace on the current page load shows no failed requests. The dev server on :5173 is
externally managed (not started via this session's tooling), so it couldn't be restarted to clear
the stale HMR buffer directly — noting this rather than claiming a clean console that wasn't
independently confirmed.

## What this means for next steps

There is currently no way to reach a bug tracker, calendar, chat, invoices, or auth screen in the
running app — that is the intended state, not a bug. `/design-system` is now the pattern reference
for every page that gets rebuilt from here, each wired back into `AppRoutes.tsx` as it's done. The
`.agents/template/*.html` files remain the layout source per
[`template-adoption.md`](../guides/template-adoption.md); the hooks/services above are ready and waiting for
whichever page gets rebuilt first.
