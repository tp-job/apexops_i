## Breaking changes

- **`user_settings.session_timeout` default changed from 30 to 480 minutes.** Existing rows still
  holding the untouched default of 30 are migrated to 480 by a one-time script
  (`npm run migrate:session-timeout`) run as part of Sprint 5, so no existing account is affected by
  a value nobody chose. ([`2f3b855`](https://github.com/tp-job/apexops_i/commit/2f3b855))
- **`GET /api/auth/profile` and `PUT /api/auth/settings` no longer return or accept the ten
  unenforced account-settings toggles** (`emailNotifications`, `twoFactorAuth`, `loginAlerts`, etc.).
  Any client reading those fields now gets `undefined`. ([`2f3b855`](https://github.com/tp-job/apexops_i/commit/2f3b855))
- **`package-lock.json` is no longer git-ignored.** Anyone with a stale local ignore rule or CI config
  assuming the lockfile is absent should re-check `npm ci` behavior. ([`e61025a`](https://github.com/tp-job/apexops_i/commit/e61025a))

## Delivered

### Sprint 3 — Session refresh ([`d80675e`](https://github.com/tp-job/apexops_i/commit/d80675e))

- **Tokens no longer expire mid-session under concurrent requests.** `lib/authSession.ts` is now the
  single refresh coordinator: concurrent 401s are single-flighted instead of each rotating the other's
  single-use refresh token out from under it.
- **Every HTTP transport retries through the same path.** `api/client.ts`, `services/api.ts`,
  `services/auth.ts`, and the note/calendar/chat/dashboard call sites (`noteAi.ts`, `noteApi.ts`,
  `useDashboardStats.ts`, `useNoteStatsOverview.ts`, `calendarApi.ts`, `chatApi.ts`) all retry exactly
  once through the coordinator, closing a gap where `AuthContext.refreshToken()` had sat uncalled since
  Sprint 1.

### Sprint 4 — Source maps ([`a1c49c7`](https://github.com/tp-job/apexops_i/commit/a1c49c7))

- **A minified stack frame now resolves to original file, line and function** on the issue detail
  screen, symbolicated at read time (not ingest time) so a map uploaded after a deploy's first errors
  retroactively resolves events already stored.
- **Uploaded source maps are stored in Postgres, never on disk**, and `content` is selected by exactly
  one server module (`lib/sourcemaps.ts`) — closing the path by which a misconfigured static route
  could have published a customer's original source.
- **Symbolication fails open everywhere.** A corrupt map, wrong release, or unparseable stack returns
  the raw frame rather than an error.
- New: `StackPanel` / `SourceMapsPanel` on the client with a view-minified toggle; `SourceMap` model
  and `lib/stackFrames.ts` / `lib/sourcemaps.ts` on the server.
- **Not landed:** first-seen-in-release and regression-in-a-newer-release tracking, cut and documented
  as needing a release-ordering decision that belongs in a spec, not an implementation (see *Not
  landed* below).

### Sprint 5 — Settings & roles ([`2f3b855`](https://github.com/tp-job/apexops_i/commit/2f3b855))

- **Session timeout is now real, on both tokens.** `sessionTimeout` bounds the access token's
  `expiresIn` *and* the refresh token's sliding idle window (`lib/sessions.ts`) — sizing only the
  access token would have enforced nothing observable, since the client silently re-issues an expired
  one.
- **Sessions now actually expire.** An absolute 7-day cap is carried forward through every token
  rotation, closing an existing hole where a continuously-refreshed session never expired.
- **Role changes take effect on the next request, not on token expiry.** `authorize()` now resolves
  `role` and `isActive` from the database instead of trusting the JWT claim — closing the
  token-invalidation-on-role-change risk carried in every sprint plan before this one.
- **Fixed a live bug:** `GET /sessions` computed the `current` session flag from `req.body` on a GET
  request, so it was always `false` — meaning the "current session" Sign-out control could revoke the
  session actually in use. The access token now carries a `sid` claim identifying its own session.
- New: `/admin/users` screen, `GET`/`PATCH /api/users` routes, per-account theme (moved off
  localStorage-only), timezone as a bounded `Select` instead of free text.

### Sprint 7 — Platform hardening ([`e61025a`](https://github.com/tp-job/apexops_i/commit/e61025a))

- **Closed an open, unmetered AI proxy.** `POST /api/ai/chat` had no authentication, no rate limit,
  and no input cap — verified live pre-fix, an anonymous request reached Google. Now gated by auth, a
  per-user quota, prompt/history size caps, and a lower output ceiling, with every rejection happening
  *before* the outbound call so a refused request never spends the API key's money.
- **Closed an unauthenticated SSRF endpoint.** `POST /api/console-logs` accepted an arbitrary URL and
  drove a headless browser to it, reachable including `169.254.169.254` (cloud instance metadata). Now
  admin-gated, rate-limited, and checked by `lib/urlGuard.ts`, which resolves DNS and refuses
  private/loopback/link-local/reserved addresses rather than pattern-matching hostnames.
- **The repository has a test suite for the first time.** Vitest wired into both workspaces (`npm test`
  from the repo root), covering fingerprint grouping, timezone resolution, stack-frame parsing, and
  session-timeout clamping — the exact functions four consecutive sprints had named as "first things
  worth testing." Verified to actually catch regressions by reintroducing two real past bugs and
  confirming the correct test failed each time.
- **The repository has CI for the first time.** `.github/workflows/ci.yml` runs typecheck, lint, test,
  and build on every PR and push to `main` — no deploy step, no secrets required, so a fork PR gets the
  same checks as a branch on the repo.
- **Fixed a supply-chain gap.** `package-lock.json` was git-ignored, meaning `npm ci` was never
  reproducible — the direct cause of Sprint 4 silently resolving a different `source-map` dependency
  version than intended. Now tracked.
- **Email has a real transport.** `lib/mail.ts` (console/SMTP/noop drivers) is wired to invites and
  regression alerts, verified by reading a delivered message back off the wire rather than trusting a
  resolved `sendMail()` promise. Sends are detached and timeout-bounded so a slow mail server can never
  delay or fail the request that triggered them.

## Fixes

- **Concurrent 401s no longer invalidate each other's refresh tokens**, which previously could log a
  user out while they were actively using the app. ([`d80675e`](https://github.com/tp-job/apexops_i/commit/d80675e))
- **The "current session" indicator and its Sign-out control now identify the right session**, instead
  of always reporting `current: false`. ([`2f3b855`](https://github.com/tp-job/apexops_i/commit/2f3b855))
- **Sessions now expire.** A repeatedly-refreshed session previously had no upper bound on lifetime.
  ([`2f3b855`](https://github.com/tp-job/apexops_i/commit/2f3b855))
- **Role demotion/promotion now takes effect immediately** rather than waiting for the holder's token
  to expire. ([`2f3b855`](https://github.com/tp-job/apexops_i/commit/2f3b855))
- **`POST /api/ai/chat` no longer usable by an anonymous, unmetered caller.**
  ([`e61025a`](https://github.com/tp-job/apexops_i/commit/e61025a))
- **`POST /api/console-logs` no longer usable as an internal-network SSRF probe.**
  ([`e61025a`](https://github.com/tp-job/apexops_i/commit/e61025a))
- **`npm ci` is now reproducible** — previously unpinned dependency resolution had already caused one
  incorrect dependency version to ship silently. ([`e61025a`](https://github.com/tp-job/apexops_i/commit/e61025a))
